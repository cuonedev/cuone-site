# 多 Agent 协作实践：系列规划

## 系列定位

从真实开发中的 Agent 协作断点出发，使用社区 MCP 项目跑通本机与局域网协作，再结合实际使用梳理消息追踪和工程化需求。

文章面向使用 AI 辅助开发的读者，重点记录实际问题、选择依据、验证过程和阶段结论。社区项目的能力、方案边界和工程化决策，以调研或实测结果为准，不预先写成已验证结论。

## 系列主线

**协作问题 → MCP 项目使用 → 本机与局域网协作 → 工程能力梳理 → Java 工程化 → 使用复盘**

每篇只回答一个主要问题。前一篇的实际发现决定后一篇的关注点；如果验证结果与预期不同，就调整后续选题，不为了凑篇数重复介绍概念或预设产品结论。

这里的“主线”表示内容之间的逻辑推进，不要求按固定频率连续发布。每篇正文都应补足必要背景、独立成立；读者不需要按编号顺序阅读才能理解单篇文章。

## 暂不作为主线的路线

第一篇已经概览社区常见路线。后续文章不再重复做路线大全，而是围绕 MCP 项目实测。其他路线保留作比较背景，是否重新评估取决于实测中暴露的差距。

| 路线 | 代表方向 | 当前定位 |
|---|---|---|
| Agent 间开放协议 | A2A | 关注现有编码 Agent 的原生支持或适配成本；协议本身不等于可直接使用的共享消息服务。 |
| 单一工具内置团队 | 各编码工具的子 Agent / 团队功能 | 适合作为同一工具内的协作能力参照，是否能覆盖跨工具、跨人员需求需看具体接口。 |
| 终端或会话桥接 | WezTerm Chat MCP、Modula Relay | 适合作为本机工作流参照，结合项目实际确认终端依赖和跨环境能力。 |
| 面向特定工具的通信插件 | Agent Message Bus 等 | 关注支持的宿主范围、维护状态和与共用 MCP 接入方向的差异。 |
| 独立 Agent 通信服务 | cross-agent-teams-mcp、October Bus 等 | 作为重点调研对象之一；具体能力、配置和部署边界以仓库资料及实测为准。 |

“暂不作为主线”是当前选题和验证顺序的安排，不代表否定或永久排除。通信协议、服务部署形态和 Agent 接入方式属于不同层次；MCP 是接入方式之一，具体消息、编排和唤醒能力由服务及宿主实现。
